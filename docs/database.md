# Database Architecture & Design

## 1. Schema Overview
The Lost & Found Intelligence System employs a relational database design conforming to Third Normal Form (3NF). It is engineered for MySQL 8.0+ and runs out-of-the-box in local development via an embedded H2 engine in MySQL mode.

## 2. Table Specifications

### 2.1 `users`
Stores student and staff credentials with BCrypt password hashing and role assignments.
- `id` (BIGINT, PK, AUTO_INCREMENT)
- `name` (VARCHAR(100), NOT NULL)
- `email` (VARCHAR(150), NOT NULL, UNIQUE, Indexed)
- `password_hash` (VARCHAR(255), NOT NULL)
- `phone` (VARCHAR(20))
- `role` (VARCHAR(30), DEFAULT 'ROLE_STUDENT', Indexed)
- `is_active` (BOOLEAN, DEFAULT TRUE)
- `created_at`, `updated_at` (TIMESTAMP)

### 2.2 `locations` (Campus Graph Vertices)
Defines physical campus landmarks and coordinates for Dijkstra distance calculations.
- `id` (BIGINT, PK, AUTO_INCREMENT)
- `name` (VARCHAR(100), NOT NULL, UNIQUE, Indexed)
- `description` (VARCHAR(255))
- `latitude` (DOUBLE PRECISION)
- `longitude` (DOUBLE PRECISION)
- `created_at` (TIMESTAMP)

### 2.3 `location_edges` (Campus Graph Weighted Adjacency)
Persists physical walkways and pedestrian paths between campus locations.
- `id` (BIGINT, PK, AUTO_INCREMENT)
- `source_location_id` (BIGINT, FK -> locations.id, Indexed)
- `target_location_id` (BIGINT, FK -> locations.id, Indexed)
- `distance_meters` (INT, NOT NULL): Edge weight in meters
- `is_bidirectional` (BOOLEAN, DEFAULT TRUE)

### 2.4 `lost_items` & `found_items`
Tracks user-reported items and operational status.
- `id` (BIGINT, PK, AUTO_INCREMENT)
- `user_id` (BIGINT, FK -> users.id, Indexed)
- `title` (VARCHAR(150), NOT NULL)
- `category` (VARCHAR(50), NOT NULL, Indexed)
- `brand` (VARCHAR(80), Indexed)
- `color` (VARCHAR(50), Indexed)
- `description` (TEXT, NOT NULL)
- `location_id` (BIGINT, FK -> locations.id, Indexed)
- `lost_date` / `found_date` (DATE, NOT NULL, Indexed)
- `lost_time` / `found_time` (TIME, NOT NULL)
- `status` (VARCHAR(30), DEFAULT 'ACTIVE', Indexed): ACTIVE, MATCHED, CLAIMED, RESOLVED, CANCELLED
- `image_url` (VARCHAR(500))
- `created_at`, `updated_at` (TIMESTAMP)

### 2.5 `match_results`
Stores deterministic matching breakdowns generated by the Java Matching Engine.
- `id` (BIGINT, PK, AUTO_INCREMENT)
- `lost_item_id` (BIGINT, FK -> lost_items.id, Indexed)
- `found_item_id` (BIGINT, FK -> found_items.id, Indexed)
- `match_score` (INT, NOT NULL, Indexed DESC)
- `category_score` (INT, 0 or 20)
- `brand_score` (INT, 0 or 10)
- `color_score` (INT, 0 or 15)
- `keyword_score` (INT, 0 to 20)
- `description_score` (INT, 0 to 10)
- `location_score` (INT, 2 to 15)
- `date_score` (INT, 0 to 5)
- `time_score` (INT, 0 to 5)
- `distance_meters` (INT, NOT NULL): Dijkstra shortest path
- `route_path` (TEXT): Sequence of campus nodes
- `explanation` (TEXT): Human-readable matching reasoning
- `created_at` (TIMESTAMP)

### 2.6 `claims`
Ownership claim requests submitted by students.
- `id` (BIGINT, PK, AUTO_INCREMENT)
- `found_item_id` (BIGINT, FK -> found_items.id, Indexed)
- `claimant_user_id` (BIGINT, FK -> users.id, Indexed)
- `description` (TEXT, NOT NULL): Private identifiable proof
- `status` (VARCHAR(30), DEFAULT 'PENDING', Indexed): PENDING, APPROVED, REJECTED
- `created_at`, `reviewed_at` (TIMESTAMP)
- `reviewer_notes` (VARCHAR(255))
